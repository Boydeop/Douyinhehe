# Douyinhehe 3.7 RC1: full-code audit and desktop UX acceptance

Date: 11 November 2026. Based on the repository's `main` at 3.6.0rc1,
then audited on `audit/studio-3-7-quality-ui`. This report explicitly
separates source inspection and automated tests from the manual Windows and
live Douyin acceptance tests that cannot be simulated here.

## Key changes verified in source

| Subsystem | Finding (severity) | Implementation |
| --- | --- | --- |
| Qt UI | Only dark mode, nine pages were difficult to discover (P2) | New single-source dark/light QSS theme, persistent QSettings preference and geometry |
| Navigation | Long sidebar and many settings with no feature search (P2) | Ctrl+K page search, Ctrl+L link input, existing Ctrl+1..5 workspace shortcuts |
| Downloader | No self-service diagnostic separating a broken F2 worker from blocked Douyin (P1) | Offline F2 `--doctor` and yt-dlp status, with user-visible report; zero network/cookie use |
| Download workflow | Excessive clicks to paste a link/open destination (P2) | Paste/clear URL and open local downloads folder |
| Editor | Selecting a new clip could inherit unsaved cut/mask/CTA settings (P1) | Per-clip in-memory edit state, restored when revisiting |
| Editor | Rapid A→B→A transitions could accept a stale ffprobe/frame job (P1) | Generation-based guards for metadata and preview jobs |
| Editor | Removing an item could leave a new highlighted item with no active source (P1) | Reconcile selected clip after removal |
| Editor | An old 5-second render could begin playing while a different clip is selected (P1) | Generation guard before switching player to preview output |
| Logs | Generic share-link query secrets could be logged (P1) | Redact share_token, access_token, signature and related parameters |
| Testing | Prior UI checks did not cover theme/search and edit state (P1) | Frozen PyInstaller GUI smoke, WCAG text/contrast, downloader health tests |

## Broader subsystem audit, with explicit boundaries

- **Download:** HTTPS Douyin host validation, F2 worker `one/post`,
  conditional yt-dlp fallback, duplicates and nonempty MP4 detection. No
  automatic 403, CAPTCHA, authentication bypass or private-video support.
  A green `--doctor` does not prove a live source can be downloaded.
- **Video editor:** local playable workspace, seeking, IN/OUT, masks, selected
  frame OCR, color, aspect, 5-second preview, source-safe FFmpeg export and
  per-clip in-session state. Not a multitrack CapCut timeline; time-varying OCR
  mask tracking and complex transitions are not claimed.
- **OCR and subtitles:** RapidOCR/ONNX packaged offline, Chinese frame
  proposals, optional Whisper transcription and Gemini SRT translation. The
  OCR frames are sampled; subtitle motion needs manual review. Gemini quota
  and available models are project-specific and require explicit confirmation.
- **Batch:** persisted SQLite render queue, retry and provenance data. Task
  cancellation, resumable F2 downloads and hard disk budget controls remain
  open product improvements.
- **Account security:** keyring for API credentials, sanitized local log,
  explicit external API opt-in. Source-confirmation does not verify copyright
  ownership; manual rights audit remains essential.
- **Publishing:** Postiz API integration is separate. Remote OAuth, actual
  platform posting and approval must be verified with authorized accounts.
- **Windows:** Python checks Windows/Ubuntu, PyInstaller onedir portable with
  FFmpeg, F2, OCR and Qt Multimedia self-tests. A CI pass is not interactive
  mouse/keyboard playback testing or proof of correct third-party license
  redistribution.

## Adopted design/agent references (not bundled as runtimes)

1. [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill),
   MIT: semantic design tokens, hierarchy, focus, contrast. Web-centric
   examples are adapted manually to Qt QSS.
2. [Impeccable](https://github.com/pbakaus/impeccable), Apache-2.0:
   `audit`/`harden`/`polish` heuristics for error states, layout and
   keyboard navigation. Its web detector is NOT presented as a validated
   PySide6 checker.
3. [ffmpeg-skill](https://github.com/kajisho5/ffmpeg-skill), MIT:
   deterministic probe → transform → verify and video-only quality gates.
4. [video-editing-skill](https://github.com/kajisho5/video-editing-skill),
   MIT: typed operation boundaries and reproducible exports. A full operation
   graph is future work, not yet integrated.
5. [PyQt-Fluent-Widgets](https://github.com/zhiyiYo/PyQt-Fluent-Widgets):
   visual reference only. GPL/commercial licensing and extra packaging
   complexity make it unsuitable for unreviewed import into this MIT affiliate
   application.
6. Unmerged historical PR #9 supplied a reference for a two-mode Qt palette;
   only compatible, verified ideas are ported. Keep 3.6 download→editor flow.

## Release gate and limitations

- Linux and Windows unit tests must pass at the *integration head*.
- Windows portable build must pass OCR, F2 `--doctor`, FFmpeg render and
  Qt headless UI smoke tests on the same commit.
- Re-read `main` after merge to confirm 3.7 version and changes.
- Run manual Windows acceptance on an authorized sample MP4:
  play, scrub, switch A→B→A, edit settings, remove clip, OCR,
  preview and verify exported video/audio without overwriting source.
- Run permitted public direct/short/profile URLs on the user's own network
  and attach sanitized logs for failures. Do not claim 100% cookie-free.
- Check FFmpeg/Qt license obligations and source-availability requirements
  before redistributing the portable binary commercially.
- Leave signed installer, true single-file EXE, OAuth/platform verification,
  dynamic video subtitle tracking and full NLE timeline explicitly OPEN.
